# Python Quiz Game

코데세이 E1-2 미션으로 제작한 Python 콘솔 기반 퀴즈 게임입니다.

## 1. 프로젝트 개요

Python 기본 문법과 객체 지향 프로그래밍을 활용하여 터미널에서 실행되는 객관식 퀴즈 게임을 개발했습니다.

사용자는 퀴즈 풀기, 퀴즈 추가·삭제, 퀴즈 목록 확인, 최고 점수 확인, 게임 기록 조회 기능을 사용할 수 있습니다. 문제는 무작위로 출제되며, 풀 문제 수를 직접 선택할 수 있습니다. 힌트 사용 시 해당 문제의 배점이 절반으로 줄어듭니다.

퀴즈 목록, 최고 점수, 게임 기록은 JSON 파일에 저장되어 프로그램을 종료해도 유지됩니다.

## 2. 퀴즈 주제 및 선정 이유

- **주제:** Python 기초 문법
- **선정 이유:** Python 자료형, 조건문, 반복문, 함수 등 기초 개념을 퀴즈로 복습하고 학습 내용을 직접 확인하기 위해 선정했습니다.

### 클래스 구성

**Quiz**

- 문제, 선택지, 정답 번호, 힌트 관리
- 문제 출력 및 정답 판정
- 힌트 출력

**QuizGame**

- 퀴즈 목록, 최고 점수, 게임 기록 관리
- 메뉴 출력 및 사용자 입력 처리
- 퀴즈 풀기, 추가, 삭제, 목록 확인
- 무작위 출제, 문제 수 선택, 힌트 감점
- 최고 점수 및 게임 기록 조회
- JSON 데이터 저장 기능 호출

### 클래스를 사용한 이유

퀴즈 문제의 데이터와 게임 진행 기능을 구분하기 위해 클래스를 사용했습니다.

- **추상화:** `Quiz` 클래스는 문제, 선택지, 정답, 힌트를 하나의 객체로 묶어 관리합니다. 게임 진행 코드는 문제 데이터의 내부 구조를 매번 직접 처리하지 않고 `display()`, `check_answer()` 등의 메서드를 호출합니다.
- **재사용성:** `Quiz` 객체를 여러 개 생성하여 동일한 문제 출력 및 정답 판정 기능을 반복해서 사용할 수 있습니다.
- **책임 분리:** `QuizGame`은 메뉴, 사용자 입력, 채점, 기록 관리를 담당하고, JSON 파일 입출력은 `storage.py`에서 담당하도록 분리했습니다.

이 구조를 선택한 이유는 문제 데이터, 게임 진행 방식, 저장 형식 중 하나를 수정할 때 다른 부분에 미치는 영향을 줄이기 위해서입니다.

### 주요 파일 및 메서드 역할

| 파일 또는 메서드 | 역할 |
|---|---|
| `main.py` | `QuizGame` 객체 생성 및 실행 |
| `quiz.py` | 문제 출력, 정답 판정, 힌트 출력 |
| `QuizGame.get_number()` | 숫자 입력 및 범위 검증 |
| `QuizGame.play_quiz()` | 퀴즈 출제, 채점, 결과 계산 |
| `QuizGame.add_quiz()` | 사용자 퀴즈 등록 |
| `QuizGame.delete_quiz()` | 삭제 확인 및 퀴즈 삭제 |
| `QuizGame.show_history()` | 게임 기록 출력 |
| `quiz_data.py` | 기본 퀴즈 5개 정의 |
| `storage.py` | JSON 데이터 저장 및 불러오기 |

기본 퀴즈의 개수나 내용을 변경하려면 `quiz_data.py`의 기본 퀴즈 생성 부분을 수정합니다.

### 입력 검증 방식

메뉴 번호와 문제 수 등 숫자 입력은 `get_number()`에서 빈 입력, 숫자가 아닌 입력, 허용 범위를 벗어난 입력을 검사합니다.

퀴즈 정답 입력에서는 1~4 사이의 번호 또는 힌트 요청 `h`를 구분하여 처리합니다. 잘못된 값을 입력하면 안내 메시지를 출력하고 다시 입력받습니다.

## 7. 데이터 저장 형식

### JSON 저장 형식을 선택한 이유

JSON은 사람이 직접 내용을 읽고 수정하기 쉬운 텍스트 형식이기 때문에 선택했습니다.

퀴즈에는 문제, 선택지 4개, 정답 번호, 힌트처럼 서로 관련된 데이터가 있습니다. JSON은 객체와 배열을 사용하므로 이러한 데이터를 구조적으로 저장할 수 있습니다.

또한 Python 표준 라이브러리인 `json` 모듈을 사용하면 별도의 패키지 설치 없이 저장과 불러오기를 구현할 수 있습니다.

현재 프로젝트는 데이터 규모가 작으므로 JSON 파일로 관리하고, 데이터가 많아지거나 복잡한 검색 기능이 필요해지면 데이터베이스 사용을 검토할 수 있습니다.

프로젝트 폴더의 `state.json`에 데이터를 UTF-8 JSON 형식으로 저장합니다.

```json
{
    "quizzes": [
        {
            "question": "Python에서 정수를 나타내는 자료형은?",
            "choices": ["str", "int", "bool", "list"],
            "answer": 2,
            "hint": "숫자를 저장하는 자료형을 생각해 보세요."
        }
    ],
    "best_score": 100,
    "history": [
        {
            "datetime": "2026-11-03T17:46:06",
            "total_questions": 1,
            "correct_answers": 0,
            "score": 0
        }
    ]
}
```

- `quizzes`: 등록된 퀴즈 목록
- `question`: 문제 내용
- `choices`: 선택지 4개
- `answer`: 정답 번호 (1~4)
- `hint`: 문제별 힌트 (생략 가능)
- `best_score`: 최고 점수 (0~100, 기록이 없으면 `null`)
- `history`: 게임 플레이 기록 목록
- `datetime`: 게임을 완료한 날짜와 시간
- `total_questions`: 플레이한 문제 수
- `correct_answers`: 정답을 맞힌 문제 수
- `score`: 힌트 감점이 반영된 최종 점수 (0~100)

점수는 100점 만점으로 계산합니다. 힌트 없이 정답을 맞히면 해당 문제에서 1점, 힌트 사용 후 정답을 맞히면 0.5점을 획득하며, 총 획득 점수를 문제 수로 나누어 환산합니다.

파일이 없으면 기본 퀴즈 5개를 사용합니다. 파일 내용이 올바르지 않은 경우 오류를 안내하고 기본 데이터로 복구합니다.

### 데이터 불러오기 및 저장 시점

1. 프로그램 실행 시 `QuizGame.__init__()`에서 저장된 퀴즈와 최고 점수를 불러옵니다.
2. 게임 기록도 `load_history()`를 통해 불러옵니다.
3. 퀴즈를 추가하거나 삭제하면 변경 사항을 저장합니다.
4. 퀴즈 풀이가 끝나면 최고 점수 및 게임 기록을 갱신하고 저장합니다.
5. 정상 종료하거나 `Ctrl + C` 등으로 실행을 중단하면 저장을 시도합니다.

### 데이터 백업 및 복원

퀴즈 삭제나 데이터 변경을 테스트할 때 기존 데이터를 보호하기 위해 `state.json`을 별도 파일로 백업할 수 있습니다.

**1. 백업 생성**

프로그램을 종료한 상태에서 PowerShell을 실행합니다.

```powershell
Copy-Item .\state.json .\state_backup.json
```

**2. 백업 복원**

문제가 발생하거나 테스트를 마친 경우 백업 파일을 원래 위치로 복원합니다.

```powershell
Copy-Item .\state_backup.json .\state.json -Force
```

**3. 복원 결과 확인**

```powershell
python -c "from storage import load_state; quizzes, score = load_state(); print('퀴즈 수:', len(quizzes), '최고 점수:', score)"
```

**4. 임시 백업 삭제**

복원 결과가 정상임을 확인한 후 백업 파일을 삭제합니다.

```powershell
Remove-Item .\state_backup.json
```

이 절차는 퀴즈 삭제 기능 테스트 중 실제로 사용했습니다.

현재 프로그램은 저장 시 자동 백업 파일을 생성하지 않으므로 중요한 데이터 변경 전에는 수동으로 백업해야 합니다.

### 1,000개 퀴즈 성능 테스트

Python 표준 라이브러리의 `time.perf_counter()`와 `tracemalloc`을 사용하여 퀴즈 1,000개의 생성 시간, 검색 시간, 메모리 사용량을 측정했습니다.

테스트 환경은 Windows, Python 3.13이며 별도 테스트 파일 `performance_test.py`를 사용했습니다.

| 측정 항목 | 결과 |
|---|---|
| 생성한 퀴즈 | 1,000개 |
| 퀴즈 생성 시간 | 0.001788초 |
| 퀴즈 검색 시간 | 0.000018초 |
| 검색 결과 | 성공 |
| 현재 추적 메모리 | 279.96KB |
| 최대 추적 메모리 | 280.37KB |

테스트는 `Quiz` 객체 1,000개를 리스트에 생성하고 마지막 문제를 순차 검색하는 방식으로 진행했습니다.

측정 결과, 해당 환경에서 1,000개 객체의 생성과 검색이 정상 완료됐습니다.

다만 이 결과는 단일 실행 측정값이며, JSON 파일 저장·불러오기 속도나 전체 게임의 응답 속도를 측정한 결과는 아닙니다. `tracemalloc`의 수치도 Python이 추적한 메모리이며 프로그램 전체 메모리 사용량과는 차이가 있습니다.

퀴즈 수가 크게 증가하면 현재의 리스트 순차 검색과 JSON 전체 저장 방식에 성능상 한계가 있을 수 있습니다. 필요하다면 검색용 자료구조나 데이터베이스 도입을 검토할 수 있습니다.

### 커밋 단위

- 하나의 기능 구현이나 문서 수정이 완료되면 커밋합니다.
- 서로 관계없는 변경 사항은 가능한 한 별도 커밋으로 분리합니다.
- 커밋 전 변경 파일과 실행 결과를 확인합니다.

### 커밋 메시지 규칙

`유형: 변경 내용` 형식을 사용했습니다.

- `Feat`: 새로운 기능 구현
- `Fix`: 오류 수정
- `Refactor`: 코드 구조 개선
- `Docs`: README 및 스크린샷 등 문서 작업
- `Test`: 기능 테스트 및 검증 기록
- `Data`: 퀴즈 데이터 변경
- `Chore`: 프로젝트 초기 설정 및 관리

실제 커밋 예시:

- `Feat: implement quiz play and score calculation`
- `Refactor: organize game features into QuizGame class`
- `Docs: update README with bonus features`

GitHub 원격 저장소는 `origin`으로 등록했고, 기능 개발 후 `git push origin main`으로 변경 사항을 업로드했습니다.

브랜치 작업에서는 `feature/quiz-play`에서 기능을 구현한 뒤 `main`에 Fast-forward 방식으로 병합했습니다. GitHub 초기 커밋은 별도의 병합 커밋으로 통합했습니다.
